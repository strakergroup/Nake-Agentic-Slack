# Changelog

All notable changes to this project will be documented in this file.

## Changes

- [Changed]: RAY-80512 — removed new-post bot debounce; each separate channel message translates on its own (placeholder skip + rate limit still apply). Edit coalescing remains via per-`ts` generation counter on `message_changed` only (Wade Norman, 2026-07-02)
- [Fixed]: RAY-80512 — bot channel auto-translate now skips placeholder-only messages (Slack `:emoji:` tokens, bare ellipsis `...`/`…`, punctuation, Unicode emoji — via `is_untranslatable_placeholder`), discards stale MT callbacks via per-message edit generation on edits, excludes edits from the bot rate limit, and writes the translation reply cache synchronously so edit delivery can reliably `chat.update` (Wade Norman, 2026-07-02)
- [Changed]: RAY-80512 — bot-message debounce now runs as a deferred, unique-keyed SAQ job (`translate_debounced_bot_message`, `scheduled` support added to the enqueue wrapper) instead of a fire-and-forget asyncio task, so a burst of streaming bot posts collapses to one durable translation of the latest payload; removed the now-unused `persist_mt_ts_edit` task/`enqueue_mt_ts_edit` helper (the reply-cache write is synchronous) (Wade Norman, 2026-07-02)
- [Changed]: RAY-80492 — inline/channel MT charge sends `submission_group_uuid` (message ts or channel+content anchor) to `/mt/inline-usage` so IBM usage report grouping no longer relies on heuristics for new debits (Wade Norman, 2026-07-01)
- [Added]: RAY-80417 — billing tasks (`charge_document_mt`, `charge_inline_mt_usage`) now raise a Google Chat alert immediately on the first attempt when the LanguageCloud gateway rejects a charge with a non-retryable 4xx (e.g. 422 contract/deploy mismatch, 403), instead of staying silent until the final SAQ attempt; `charge_document_mt` also logs a WARNING when the gateway replays a charge on the first attempt (no new debit). Shared `_alert_gateway_billing_failure` helper; retains the existing final-attempt alert for transient errors (Wade Norman, 2026-06-29)
- [Fixed]: RAY-80384 — Slack HV quote Estimated Completion now uses global max turnaround across selected file/language pairs (aligned with Verify `create_tp_job` due-date logic) instead of max × target count; checkbox deselect recalculates from remaining selections via the same helper (Wade Norman, 2026-06-26)
- [Changed]: RAY-80417 — Slack document MT is now billed only after successful delivery: `slack_upload_mt_result` enqueues `charge_document_mt` (background SAQ) which relays the prepared `mt_charge` payload from the `verify:slack:document:translated` event to `/mt/transaction`, charging document MT and the combined PDF conversion fee in one call. Teams now follows the same pattern in ms-teams-ray-translator (`chargeTeamsDocumentMt`); int-slack charges nothing for either path (Wade Norman, 2026-06-26)
- [Changed]: RAY-80417 — the deferred PDF conversion fee is now billed from the `verify:slack:document:translated` event payload (new `pdf_conversion_page_count`/`pdf_source_file_name`/`pdf_gridfs_file_id` fields on `MtSuccessResponseSchema`) instead of a `slack_job.extra_data` hand-off. `slack_upload_mt_result` no longer reads `slack_job`; `build_pdf_conversion_billing`/`pdf_conversion_billing_pending` take the event; removed `update_slack_job_extra_data` and the `pdf_conversion_fee_charged` flag (gateway idempotency key dedupes) (Wade Norman, 2026-06-26)
- [Changed]: RAY-80417 — de-duplicated the client-lookup + id-token minting copy-pasted across `log_transcribe_by_client_id`, `log_embedding_by_client_id`, `log_inline_mt_usage_by_client_id`, and `log_pdf_conversion_fee_by_client_id` into one `_id_token_for_client(client_id, allow_group_fallback=...)` helper (group fallback preserves channel auto-translate org billing) (Wade Norman, 2026-06-26)
- [Added]: RAY-80417 — spend producers stamp `submission_group_uuid` so a submission's debits group in the IBM usage report: transcription and embedding send the media task uuid (ties transcribe→SRT translate→embed); the deferred PDF conversion fee sends the slack_job task uuid (ties it to the document-MT debit). Threaded through `log_transcribe_by_client_id`, `log_embedding_by_client_id`, `log_pdf_conversion_fee_by_client_id`, and `build_pdf_conversion_billing` (Wade Norman, 2026-06-26)
- [Changed]: RAY-80417 — PDF conversion fee for Document MT is deferred until the translated file is delivered to Slack: `slack_upload_mt_result` enqueues durable `charge_pdf_conversion_fee` (background SAQ) after a successful upload; fee payload includes `submission_group_uuid` (slack_job task uuid) linking it to the document-MT debit; conversion cost is absorbed on extract/merge/translation/delivery failures. Adds `log_pdf_conversion_fee_by_client_id`, `app/slack/pdf_conversion_spend.py`, and `docs/document-mt-pdf-billing.md` (Wade Norman, 2026-06-26)
- [Changed]: RAY-80258 — inline/channel/shortcut MT billing is now deferred to a durable SAQ job (`charge_inline_mt_usage`, background queue) instead of running synchronously in the `slack:direct:mt:result` callback. A transient `ConnectTimeout` to `/mt/inline-usage` no longer returns a 422 to `redis-slack-consumer` after the Slack message was posted; the charge retries with `retry_on_timeout` + gateway idempotency and then writes the Google API usage row against the resulting `transaction_uuid`.
